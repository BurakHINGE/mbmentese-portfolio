GHOSTHUNTER INC.

Java JavaFX 2D Game Dev No Game Engine
+3
OOP Game Loop Co-op Dev

Hazır bir oyun motoru kullanılmadan, tamamen sıfırdan kodlanmış 2D hayalet avlama ve hayatta kalma oyunu.

A 2D ghost hunting and survival game coded entirely from scratch without using a ready-made game engine.

Çıkış Noktası ve Kapsam Starting Point and Scope

Bir üniversite projesi olarak temelleri atılan GhostHunter, zamanla orijinal kapsamını aşarak uzun soluklu bir oyun geliştirme serüvenine dönüştü. Amacımız sadece eğlenceli bir oyun yapmak değil; OOP prensiplerini kullanarak, dışarıdan hazır bir oyun motoruna bağımlı kalmadan kendi oyun mekaniklerimizi sıfırdan inşa etmekti.

Starting as a university project, GhostHunter eventually exceeded its original scope and turned into a long-term game development adventure. Our goal was not just to make a fun game, but to build our own game mechanics from scratch using OOP principles, without depending on an external game engine.

Görünmez Tehditler

Invisible Threats

2D harita üzerinde gezinirken, çıplak gözle görülemeyen hayaletleri tespit etme mekaniği.

Mechanics to detect ghosts invisible to the naked eye while navigating the 2D map.

Tarayıcı Silah

Scanner Gun

Hayaletleri tarayıp silahın içine çekerek yok etmeye dayalı özel bir savaş (combat) sistemi.

A unique combat system based on scanning and sucking ghosts into the gun to destroy them.

Dinamik Zorluk

Dynamic Difficulty

Bölümler ilerledikçe farklılaşan ve zorlaşan yeni hayalet türleri ile sürekli artan aksiyon.

Constantly increasing action with new ghost types that diversify and become harder as levels progress.

Takım Çalışması

Teamwork

Çoklu geliştirici ortamında task ve branch yönetimi ile profesyonel ilerleme.

Professional progression with task and branch management in a Co-op Dev environment.

A custom Thread architecture was written to synchronize physics updates and framerate (FPS).

Graphics and UI

Interactive menus, button designs, and sprite rendering were handled via JavaFX using the modern structure of Java 21.

Bounding-box algorithms were developed from scratch for character, projectile, and environment interactions in 2D space.

Karşılaşılan Zorluklar ve Kararlar Challenges and Decisions

  • Motor Kullanmama Kararı: Sahneler arası geçiş, sprite yönetimi ve düşman yapay zekasının arka plandaki mantığını kavramak için standart editörlerde Java/JavaFX kullanmayı tercih ettik. Bu durum, geliştirme süresini uzatsa da temel programlama ve OOP mantığını kavramak adına çok değerli bir deneyim oldu.
  • Performans Optimizasyonu: JavaFX esasen masaüstü form uygulamaları için tasarlandığından, ekranı sürekli yenileyen bir oyun döngüsünde bellek yönetimini sızıntısız bir şekilde ayarlamak, objeleri anlık oluşturmak yerine havuzlama (object pooling) mantığına yaklaşmak teknik olarak öğretici bir meydan okumaydı.
  • Decision Not to Use an Engine: We preferred using Java/JavaFX in standard editors to grasp the background logic of scene transitions, sprite management, and enemy AI. Although this prolonged the development time, it was a highly valuable experience for understanding fundamental programming and OOP concepts.
  • Performance Optimization: Since JavaFX is primarily designed for desktop form applications, adjusting memory management without leaks in a continuously refreshing game loop, and adopting an object pooling approach instead of instantiating objects on the fly, was a technically instructive challenge.
